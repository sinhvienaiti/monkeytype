Khi recommendation chưa tốt, cần kiểm tra catalog và behavior cùng lúc. Product data đã sync chưa. Recommendation type dựa trên catalog hay hành vi. View, add to cart và place order có đủ volume không. Mobile app và kiosk có được instrument không. Sku có nhất quán không. Duplicate view có làm lệch popularity không. Bot hoặc test traffic có làm bẩn dữ liệu không. Catalog có quá rộng so với traffic trên mỗi sku không. Unit có đang hiển thị backup recommendation không. Consent rate có giảm mạnh không. Không nên kết luận machine learning sai chỉ vì một shopper thấy kết quả chưa phù hợp. Cũng không nên tạo event giả trực tiếp trên production. Một cách đánh giá tốt là theo dõi readiness, event coverage, kết quả trên nhiều journey và xu hướng metric trong khoảng thời gian đủ dài. Đánh giá nên tách chất lượng association giữa sản phẩm với mức độ cá nhân hóa cho từng shopper, vì hai kết quả này không hoàn toàn giống nhau. Nên so sánh nhiều nhóm shopper và nhiều vị trí unit thay vì chỉ nhìn homepage.

Monitoring production nên theo dõi nhiều hơn dashboard cuối cùng. Đội dự án cần biết tỷ lệ page load SDK và Collector thành công, event request success, event volume theo type và storefront, duplicate rate, payload thiếu context, consent rate, chênh lệch giữa order thật và place order event, recommendation request error và empty unit rate. Alert nên dựa vào thay đổi. Ví dụ, place order event giảm mạnh sau deployment trong khi order database không giảm. Product view trên mobile về gần không nhưng desktop bình thường. Unit render vẫn cao nhưng click biến mất. Một store view gửi event sang data space khác. Những tín hiệu này giúp phát hiện regression trước khi merchant nhận ra recommendation kém dần. Event collection là một data product cần owner, test và monitoring, không phải đoạn JavaScript cài một lần rồi quên. Monitoring cũng cần phân biệt giảm event do traffic thật giảm với giảm event do deployment làm hỏng instrumentation, bằng cách đối chiếu nguồn traffic độc lập. Dashboard nội bộ về health của event pipeline nên được review cùng dashboard marketing.

Best practice là lập event matrix trước khi code. Mỗi page và journey phải có event mong đợi, context, identifier và cách verify. Tách event phục vụ model khỏi event phục vụ dashboard. Dùng event reference hiện hành thay vì nhớ tên từ tài liệu cũ. Thiết lập page và storefront context ở application layer. Giữ sku, parent sku và unit id nhất quán. Instrument mọi channel tạo doanh thu đáng kể. Tôn trọng consent và không gửi thông tin cá nhân. Preserve tracking contract khi customize template. Cleanup listener trong SPA. Test duplicate. Verify bằng Network và Snowplow trước khi chờ dashboard. Dùng dữ liệu gần production để đánh giá readiness. Phân biệt fallback với personalized result thật. Xem dashboard như hệ thống đo lường có thể under report, không phải sổ cái giao dịch. Review release note của module, SDK và Collector trước mỗi upgrade. Khi thực hiện đầy đủ các bước này, Product Recommendations mới có dữ liệu đủ sạch để tạo gợi ý và số liệu đủ tin cậy để merchant đánh giá hiệu quả. Mỗi thay đổi frontend ảnh hưởng product card, cart hoặc checkout cần có owner xác nhận event vẫn đúng.
