Mỗi loại có lifecycle và nơi lưu khác. DI configuration chủ yếu trả lời object nào được tạo và dependency nào được dùng, không phải thay thế hệ thống quản lý cấu hình.

Preference, plugin, virtual type, decorator, factory và proxy giải quyết những vấn đề khác nhau. Preference chọn implementation mặc định cho abstraction. Plugin chèn logic quanh public method của target. Virtual type tạo biến thể constructor cho một consumer. Decorator wrap interface bằng service mới và delegate vào implementation bên trong. Factory tạo instance mới với runtime input. Proxy trì hoãn service đắt. Khi chỉ một consumer cần formatter khác, global preference là quá rộng. Khi cần bổ sung validation trước public method của module khác, plugin có thể phù hợp. Khi behavior mới là một layer rõ trên contract, decorator thường dễ test hơn chain plugin. Khi cần export job mới cho mỗi request, factory đúng hơn non shared service tùy tiện. Khi constructor archive service đắt nhưng branch hiếm, proxy có thể hợp lý. Chọn extension mechanism theo phạm vi thay đổi, không theo cơ chế quen tay. Một thiết kế hẹp giảm conflict với module khác và giúp graph dễ giải thích hơn trong review. Việc ghi rõ lý do lựa chọn trong code review giúp team tránh thay đổi phạm vi rộng ngoài dự kiến.

Review dependency injection cần nhìn cả code, xml, generated output và vận hành. Constructor phải khai báo đúng service, không có side effect nặng và không quá nhiều responsibility. Interface phải có contract rõ. Preference phải ở đúng scope và không conflict. Argument name phải khớp parameter. Array key phải có quy ước. Virtual type phải đại diện use case rõ và không quá sâu. Shared service không giữ runtime state. Factory tạo newable object. Proxy chỉ được dùng sau measurement. Global và area configuration phải được test ở entry point tương ứng. Compile phải chạy trong build pipeline. Generated code không được sửa. Công cụ xem DI info phải được dùng khi graph không như mong đợi. Integration test nên chứng minh implementation cuối, pool key và lifecycle trong đúng area. Khi các phần này được kiểm soát, dependency injection trở thành nền tảng giúp module loose coupling và dễ thay đổi. Nếu chỉ xem DI như cách để framework tự new class, developer sẽ bỏ qua scope, lifecycle, compatibility và conflict, là những phần quyết định chất lượng production.
