Mỗi triệu chứng cần được nối với layer đúng là logic criteria, collection processor, sql, serialization, authorization hoặc infrastructure. Việc ghi lại request id xuyên qua proxy, php và database trace giúp nối triệu chứng ở nhiều layer thành một incident timeline rõ ràng.

Best practice là giữ repository stateless, viết biểu thức boolean trước khi build criteria và dùng collection processor để chuẩn hóa pipeline. Hoặc nằm trong cùng group, và nằm giữa các group. Whitelist field và condition type, clamp page size, thêm unique tie breaker và test total count sau join. Authorization scope phải được áp trước pagination. Tránh N cộng một query khi hydrate list. Không kỳ vọng list response luôn có full detail. Dùng fields để giảm response nhưng vẫn đo backend cost. Với export lớn, dùng batch, snapshot hoặc checkpoint thay vì một page size khổng lồ. Theo dõi endpoint bằng metric và slow query fingerprint. Anti pattern gồm raw sql từ client, caller tự tạo collection khắp nơi, filter item sau pagination, cache không có scope, sort dựa vào thứ tự mặc định của database và distinct dùng để che one to many join. Một implementation tốt không chỉ trả đúng vài record trong test, mà còn giữ contract, permission, pagination và hiệu năng đúng khi dữ liệu lớn. Từng lỗi cần một test hồi quy riêng để lần nâng cấp sau không tái xuất hiện dưới một hình thức khác.

Để tự kiểm tra, hãy giải thích vì sao filter trong group là hoặc và group với group là và. Hãy nêu một biểu thức search criteria không biểu diễn trực tiếp, rồi chọn custom filter hoặc query service phù hợp. Phân biệt in với finset, field mapping với custom filter, items với total count và list detail với single detail. Giải thích vì sao repository phải stateless, vì sao builder state có thể rò và vì sao deterministic sort cần field duy nhất. Mô tả cách one to many join làm duplicate entity và cách exists có thể tốt hơn. Trình bày quy trình export hàng triệu record mà không tăng page size cực lớn. Nêu cách authorization được đưa vào query trước pagination. Cuối cùng, mô tả cách review một pull request thêm searchable field mới, bao gồm public contract, schema, index, rest, test, rolling deployment, observability và rollback. Khi trả lời được các câu này bằng một luồng nguyên nhân và hệ quả, người học đã hiểu repository search ở mức thiết kế production thay vì chỉ nhớ cú pháp builder.
